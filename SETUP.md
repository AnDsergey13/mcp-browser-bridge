# SETUP.md — установка и запуск моста (хост + контейнер)

## Быстрый рестарт контейнера (чеклист, ~2 минуты)

1. Хост, папка проекта: `exitbox run kimi --no-resume -- --yolo`.
2. Хост: socat-релей жив? `curl 127.0.0.1:18777` → `426 Upgrade Required`.
   Нет — перезапустить (команда ниже в §1).
3. В контейнере MCP-сервер поднимется сам из `.kimi-code/mcp.json`
   (команда `/mcp` — статус; должен быть connected). Конфиг вызывает
   `bash bridge-server/mcp-entry.sh` — скрипт сам переходит в свою папку,
   а все пути данных сервер считает от корня репо (`REPO_ROOT` в
   `src/index.ts`), поэтому ни cwd, ни env в mcp.json не нужны и перенос
   репо ничего не ломает. Диагностика процесса:
   `ss -xlnp | grep bridge.sock`.
4. Браузер: `about:debugging` → Load Temporary Add-on →
   `extension/manifest.json` (если браузер перезапускался). Открытые вкладки
   грантованных доменов переинжектируются автоматически при первом
   policy.update (П2-6) — F5 больше не обязателен; если вкладка «не
   отвечает» (CONTENT_SCRIPT_ABSENT) — перезагрузи её вручную.
5. Popup: подтверди «Новая сессия агента» → выдай session-гранты доменам
   (для курса: `course.cpsdrone.com`, `fast.wistia.com`,
   `embed-cloudfront.wistia.com`, `files.cdn.thinkific.com` —
   read+interact+download).
6. Если страница курса показала Cloudflare «Just a moment» — галочку проходит
   ЧЕЛОВЕК (агенту: СТОП и доклад, не кликать и не ждать автопрохождения).
7. Готово. Контекст задачи — в `memory/session-handoff.md`.

## Одноразовая настройка

### 1. Контейнер (ExitBox): подключение хоста к серверу

Rootless podman в ExitBox: сеть контейнера internal-only, хост до IP контейнера
НЕ достучится (проверено), флага publish портов у `exitbox run` нет. Поэтому
мост ходит через **unix-сокет в общей папке** (тот же приём, что docker.sock):
сервер слушает `.bridge/bridge.sock` в корне репозитория (путь считается от
расположения кода), а это тот же файл, что в папке проекта на хосте.

На хосте запусти релей (из любого каталога, оставить работать; сокета может
ещё не быть — скрипт ждёт его до 120 с):

```fish
bash /путь/к/mcp-browser-bridge/start-relay.sh
```

Проверка: `curl 127.0.0.1:18777` → ответ `426 Upgrade Required`. URL для
расширения: `ws://127.0.0.1:18777`. После пересоздания контейнера просто
перезапусти этот socat — путь не меняется.

Сервер продолжает слушать и TCP `0.0.0.0:18777` — если когда-нибудь появится
проброс портов, расширение можно переключить на `ws://<IP>:18777` напрямую.

Общая папка монтируется в контейнер (`/workspace`) — в корне репозитория
живут `policy.yaml`, `memory/`, `downloads/`, `.bridge/secret`, и всё это
переживает пересоздание контейнера и перенос репо (пути — от `REPO_ROOT`).

Первый старт сервера:

```bash
cd /workspace/mcp-browser-bridge/bridge-server
npm install   # один раз
npm start     # или его запустит Kimi Code CLI как MCP-сервер
```

При первом запуске в логе печатается **секрет** (лежит в `.bridge/secret`
в корне репо, права 0600). Он постоянный между контейнерами.

MCP уже настроен в `.kimi-code/mcp.json` — новые сессии Kimi Code CLI
подключают сервер автоматически (`/mcp` — статус).

### 2. Браузер (Firefox / LibreWolf)

1. `about:debugging#/runtime/this-firefox` → **Load Temporary Add-on** →
   выбрать `extension/manifest.json` из этой папки.
   (Временное расширение слетает при перезапуске браузера — загружай заново.
   Постоянная установка позже: `web-ext sign --channel unlisted`.)
2. Открыть popup расширения → **Настройки**: URL `ws://127.0.0.1:18777`,
   секрет из шага 1 → Сохранить.
3. Там же кнопка **«Выдать доступ к сайтам»** (`<all_urls>`, один раз;
   реальный доступ режется policy.yaml — default-deny).

### 2b. Браузер (Chromium / ungoogled-chromium, фаза 9)

Сборка MV3 (Firefox её не использует — там MV2, всё по-прежнему):

```bash
bash extension/build-chromium.sh   # → dist/chromium/
```

1. `chrome://extensions` → **Developer mode** → **Load unpacked** →
   `dist/chromium/`. Флаги не нужны: сборка на Manifest V3 (фон — service
   worker с keepalive: WS-трафик + будильник каждые 30 с переподключают
   соединение, если Chromium убил воркер).
2. Popup → добавить сервер (label, `ws://127.0.0.1:18777`, секрет) →
   подтвердить сессию. **Approve — per-browser:** каждый браузер подтверждает
   своё подключение из своего popup.
3. Доступы — per-browser: грант, выданный в popup Chromium, действует только
   в Chromium. В policy.yaml домен можно ограничить: `browsers: [firefox]`
   (без поля — домен доступен всем браузерам).
4. Оба браузера могут быть подключены к одному серверу одновременно;
   закрытие одного не рвёт сессию второго.
5. Подтверждённая деградация (Chromium 144 ungoogled, 2026-08-16):
   `webRequest` в MV3 service worker без bindings — `net.list` в Chromium
   НЕ работает (отвечает маркером `netlog_unavailable`). Всё остальное
   работает. HLS-скачивание через `hls-download.py --net` делай из
   Firefox-вкладки (там webRequest полноценный).

**Мульти-агентность:** в настройках popup можно держать НЕСКОЛЬКО серверов
(label/url/secret — по одному на контейнер-агент). Вкладка принадлежит
подключению, которое её открыло; «отдать текущую вкладку» другому агенту —
кнопка в popup. Чужие вкладки агенту не видны (`TAB_NOT_OWNED`);
неназначенные (открытые тобой) при нескольких серверах недоступны никому,
пока не назначишь. При одном сервере всё работает как раньше (вкладки
авто-назначаются ему).

> **Разработка: Reload расширения ≠ обновление контент-скриптов.**
> После «Reload» в `about:debugging` уже открытые вкладки продолжают
> выполнять СТАРЫЙ код content scripts (фолбэк-инжекция срабатывает,
> только если приёмник совсем мёртв). Чтобы вкладка подхватила новый
> код — перезагрузи саму вкладку (F5) или навигируй её заново.

## Каждая новая сессия (новый контейнер)

1. Запусти контейнер из папки проекта на хосте:
   `exitbox run kimi --no-resume -- --yolo`
   (папка проекта монтируется как `/workspace`).
2. Загрузи расширение, если браузер перезапускался.
3. Расширение подключится и покажет запрос **«Новая сессия агента —
   разрешить?»** (уведомление + кнопка в popup). Подтверждается **один раз
   на контейнер** — дальше все правила из `policy.yaml` действуют
   автоматически.
4. Всё. Говори агенту задачу («по пресету course выгрузи урок N…»).

Свёрнутый браузер — не помеха: соединение живёт, пока браузер запущен.
Закрытый браузер = `BROWSER_OFFLINE`.

## Управление на ходу (popup)

- **Пресет** — селектор; переключение мгновенное.
- **Грант текущему домену** — чекбоксы capabilities (`read` / `interact` /
  `download`, по умолчанию read+interact) + кнопка «Выдать / обновить грант».
  Для уже выданного домена чекбоксы предзаполнены текущими значениями —
  доступ можно поправить в любой момент. Все галочки сняты = отзыв гранта.
  Действует на сессию (живёт в памяти сервера).
- **Гранты сессии** — список выданных разовых грантов с кнопкой «Отозвать»
  у каждого: доступ закрывается мгновенно (сервер шлёт свежий policy.update,
  домен выпадает из match_patterns). Пресетные домены — правкой `policy.yaml`.
- **ПАУЗА** — красная кнопка, мгновенно останавливает агента.
- **Авто-пауза** — вкладки, остановленные из-за капчи/челленджа/2FA, с
  кнопкой «Возобновить».
- **Журнал** — 20 последних действий агента.

Gated-действия (оплата, логин, submit, удаление) показывают баннер поверх
страницы: Разрешить / Запретить / Разрешить подобные 10 мин. Таймаут
120 с = запрет.

## Правила

- Безопасность — только в `policy.yaml` (домены, capabilities, gated,
  hard_floor). Hot-reload: сохранил файл — расширение и агент получили
  обновление.
- Рекомендации по сайтам — `memory/domains/<domain>.md`, общие —
  `memory/global-notes.md`.
- Аудит всех решений — `memory/policy-audit.jsonl`; журнал шагов —
  `memory/journal.jsonl`; скачанное — `downloads/` + `downloads/manifest.jsonl`.
