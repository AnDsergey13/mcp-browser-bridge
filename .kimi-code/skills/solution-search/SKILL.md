Выполни шаги по порядку. Каждый шаг оставляет в ответе видимый след
в 1-5 строк. Шаги 0, 4 и 6 пропускать нельзя.

## Шаг 0 — Факты задачи (грунт)
Выпиши списком ВСЕ конкретики условия: числа, версии, лимиты, запреты,
имена систем. Пронумеруй: F1, F2, ...
Каждый пункт пометь [факт] (физика, данность) или [допущение] (можно оспорить).
Пример: «F3: окно простоя 15 минут [факт]»,
«F5: обрабатывать надо все записи [допущение — этого никто не требовал]».

## Шаг 1 — Функция без реализации
Одной фразой: что должно стать истинным, когда задача решена. Без слова
«как» и без названий технологий.
Плохо: «нужен более быстрый парсер».
Хорошо: «данные из X доступны в Y не позже чем через N секунд».

## Шаг 2 — Идеальный результат (ИКР), два уровня
ИКР-A: функция выполняется «сама», новых компонентов нет
(«файл уже там, где нужен», «ошибка невозможна по построению»).
ИКР-B: то же, но только из ресурсов, которые уже есть в системе.
ИКР недостижим буквально — это направление поиска: чем ближе, тем лучше.

## Шаг 3 — Ресурсы, которые уже есть
5-8 пунктов: данные, процессы, простаивающее железо, время (ночь, очередь),
установленный софт, свойства среды. Побочные эффекты — тоже ресурс
(тепло, логи, кэш, реплика, гравитация, простой).

## Шаг 4 — Три подхода, обязательно РАЗНЫХ
Подходы различаются МЕХАНИЗМОМ, не параметрами («сжать сильнее» и
«сжать другим кодеком» — один подход). По одному из трёх якорей:
- A. От ИКР назад: что должно быть истинным за шаг до цели? А за шаг
  до этого? Соедини цепочку с ресурсами из шага 3.
- B. Снятие допущения: возьми одно [допущение] из шага 0 и реши задачу
  так, будто его нет.
- C. Структурная аналогия: опиши структуру задачи одной фразой
  («поток X упирается в узкое место Y при ограничении Z») и назови
  2 области, где такая структура уже решена (техника, биология,
  логистика, экономика). Перенеси ХОД решения, не детали, и проверь
  его на ограничениях [факт].

## Шаг 5 — Дешёвая проверка до реализации
Для двух лучших подходов найди точку, где их предсказания РАСХОДЯТСЯ.
Проверь её самым дешёвым способом: мысленный эксперимент → граничный
случай (N=0, N=∞) → 5-10 строк кода → замер.
Если задача про скорость или баг: первый тест всегда «где ИМЕННО
медленно/ломается» — замер по этапам до любой оптимизации.

## Шаг 6 — Фильтр и заземление (обязателен перед финальным ответом)
1. Пройди по F1..Fn из шага 0: что учтено, что нарушено. Нарушен [факт] —
   подход отпадает; нарушено [допущение] — явно предложи его снять.
2. Противоречие «улучшили A — ухудшили B»: назови его и попробуй развести
   A и B во времени, в пространстве или по условию срабатывания.
3. Бюджет сложности: решение добавляет больше 2 новых компонентов —
   упрости или обоснуй каждый.
4. Быстро меняющийся инструмент — сверься с актуальной документацией.

Если все подходы вышли похожими — вернись к шагу 4 с другим якорем:
другое допущение, другой ресурс, другая аналогия.
